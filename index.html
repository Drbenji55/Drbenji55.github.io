Unified inside.

Storefront 01 Storefront 02 Storefront 03
Shared data model · strict store scope
01

Store isolation

Every product, order and admin view is scoped to the correct brand. Public navigation never crosses storefronts.

02

Server-first commerce

Prices and store assignment are validated on the server. Guest orders use protected access tokens.

03

Safe operational design

The preview was deliberately sandbox-first: no live payment credentials, real charges or invoicing shortcuts.

Owner experience

Professional power,
without the technical noise.

The original administration experience was reorganized around five everyday jobs: edit the site, manage products, review orders, update inventory and view the storefront.

  • One store selector updates every admin view consistently
  • Advanced tools remain available without crowding daily work
  • Guided product creation replaces database-style forms
  • Hebrew RTL and English, Spanish and German LTR

Design decisions

What made it work

Clarity

Business language first

No raw IDs, schema terminology or internal store keys appear in the owner-facing interface.

Control

Draft before public

Content follows a visible edit → save draft → preview → publish flow, with unsaved-change protection.

Access

Built for real users

RTL/LTR direction, keyboard focus, 44px targets and responsive drawers were treated as core behavior.

Trust

Fail closed

Authentication, permissions, storefront routing and order access were designed to avoid unsafe fallbacks.
